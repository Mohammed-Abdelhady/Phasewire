# Correct browser build ordering

## Task

Prepare browser acceptance with an explicit topological build so server declarations exist before the web/E2E TypeScript graph is built.

## Why

The clean browser job builds web first, but E2E support imports `@phasewire/server` types from `dist`, producing `TS2307` failures.

## Scope

**IN:** browser job preparation and the narrow build command required for `core → server → web`.

**OUT:** Playwright assertions, fixed sleeps, server implementation, and broad quality-chain optimization (T9).

## Files in scope

- **Read:** workspace package dependencies, `apps/web/tsconfig.json`, `apps/web/e2e/support/live-service.ts`, `packages/server/package.json` — establish the real declaration edge.
- **Modify:** `.github/workflows/ci.yml`; `package.json` only if a named browser-preparation script is necessary.
- **Create:** none.

## Acceptance criteria

- A clean browser job builds core before server and server before web/E2E compilation.
- Browser acceptance no longer depends on declarations left by another job or local build.
- Chromium installation and Playwright execution retain existing coverage.
- The workflow makes dependency order explicit and readable.

## Related context

Finding 5; the server package exports declarations from `dist`. T9 later removes duplicated graph entries without changing order.

## Context

`apps/web/tsconfig.json` includes E2E support, and its live-service helper imports the server facade. The browser job runs independently on a clean filesystem, so it must prepare all declaration-producing dependencies itself.

## Gotchas

Building web first can appear to pass on a dirty checkout with stale `dist`; clean-checkout ordering is the acceptance signal.
