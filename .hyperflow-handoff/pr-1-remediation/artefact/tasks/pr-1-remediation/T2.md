# Escape and validate generated frontmatter

## Task

Serialize adapter frontmatter scalars safely and add parser-backed regression coverage for every generated host document.

## Why

The plan argument hint contains quotes; wrapping it in another quoted scalar produces invalid YAML in every generated plan skill/workflow.

## Scope

**IN:** safe scalar encoding, direct YAML parser dependency if required, and all-host frontmatter parsing through renderer output.

**OUT:** checked-in generated projections (T5), review authorization policy (T3), adapter command semantics, and provider-specific behavior.

## Files in scope

- **Read:** `packages/cli/src/adapters/{catalog,hosts,install}.ts`.
- **Modify:** `packages/cli/src/adapters/render.ts`, `package.json`, `package-lock.json`.
- **Create:** `packages/cli/src/adapters/render.test.ts`.

## Acceptance criteria

- Every generated skill/workflow frontmatter block parses with a declared YAML parser.
- Every plan document yields the literal `"<goal>" [--template <id>] [--validation <check>]`.
- Serialization is generic and safe for quotes, colons, hashes, newlines, and backslashes.
- The focused change introduces no checked-in projection edits; T5 owns regeneration after T3 settles.

## Context

`AdapterSkill.argumentHint` originates in the catalog and `renderSkillMarkdown` currently nests it inside an unescaped quoted scalar. Project adapters are disposable projections of these typed sources; strict TypeScript and deterministic output are required.

## Gotchas

Escaping only double quotes is insufficient; use one general scalar serializer and verify YAML metacharacters. Leave all checked-in projections to T5.
