# Regenerate plan and review projections

## Task

Regenerate the checked-in plan and review adapter projections from the corrected renderer and catalog sources.

## Why

Generated files are disposable projections but remain checked in for four harnesses; separating their mechanical fan-out keeps the serialization and policy source commits reviewable.

## Scope

**IN:** six plan projections and seven review projections, generated with the existing project adapter installer.

**OUT:** source renderer/catalog changes, other adapter commands, unrelated generated destinations, or manual prose divergence from renderer output.

## Files in scope

- **Read:** `packages/cli/src/adapters/{catalog,render,hosts,install}.ts` — authoritative generation path.
- **Modify:** plan/review projections under `.agent/`, `.claude/`, `.codex/`, and `.grok/`, including `.claude/commands/phasewire/review.md`.
- **Create:** none.

## Acceptance criteria

- Exactly the six plan and seven review destinations change.
- Plan frontmatter parses and preserves the literal quoted goal hint.
- Review projections default to local/draft-only and require explicit target-bound authorization for one batched write.
- A second regeneration produces a clean diff.
- No generated file is manually patched away from source output.

## Test cases

| # | Scenario | Input or setup | Expected behavior | Notes |
|---|---|---|---|---|
| 1 | Plan mirror | Generate all project hosts | Six plan files contain parseable frontmatter and the literal goal hint | Serialization projection |
| 2 | Review mirror | Generate all project hosts | Seven review files share the authorization contract | Policy projection |

| 5 | Integration | Install all hosts in a temporary root and compare scoped destinations | Temporary and checked-in plan/review content match byte-for-byte | Cross-host flow |

## Related context

T2 owns renderer/parser changes; T3 owns catalog and review doctrine. Generation flows `catalog.ts` → `render.ts` → `install.ts` → `hosts.ts`.

## Context

The repository checks in project adapters for Claude Code, Codex, Grok, and Agy. These are generated artifacts, so source files remain authoritative and regeneration must be deterministic.

## Gotchas

The generator writes many destinations; stage only the six plan and seven review files and treat any additional diff as a source/idempotence problem.

## Constraints

Only modify listed generated destinations. Do not hand-edit outputs, alter source policy, bypass hooks, or name a tool as repository actor. Keep every generated Markdown file at most 350 lines and return without narrative padding.

## Security constraints

Generate into project or temporary roots only. Do not read `.env*`, certificates, keys, SSH/cloud credentials, or run destructive recursive deletion, `sudo`, `chmod 777`, force-push, package publication, or external posting. Report `BLOCKED:` if blocked access is required.

## Output format

Return exactly one: **Completed** with one line per change plus optional future-task notes; `OVERSIZE: <reason>` with a `SUGGESTED-SPLIT:` list; `CONSULT: <peer> — <question>` with at most five context lines; or `BLOCKED: <reason>`.
