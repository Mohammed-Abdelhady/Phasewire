# Gate GitHub review writes

## Task

Make the review policy source local/draft-only by default and require explicit authorization plus a resolved repository/PR target before one batched GitHub review write.

## Why

Current generated review instructions mandate comments merely because a PR is in scope, conflating review intent with authorization for external mutation.

## Scope

**IN:** catalog policy, review doctrine, posting preconditions, local fallback, batching, and renderer tests.

**OUT:** checked-in generated projections and PR template (T5/T10), GitHub API implementation, authentication, automatic posting, issue creation, or Phasewire workflow review state.

## Files in scope

- **Read:** `packages/cli/src/adapters/{render,install}.ts`.
- **Modify:** `packages/cli/src/adapters/catalog.ts`, `packages/cli/src/adapters/render.test.ts`, `AGENTS.md`, `CODE_QUALITY_AND_ENGINEERING.md`, `docs/code-review.md`.
- **Create:** none.

## Acceptance criteria

- A plain review request authorizes no GitHub write.
- Default output remains local or draft-only.
- Posting requires explicit authorization and an unambiguous repository plus PR number.
- Authorized output is one batched review; unresolved targets fall back locally.
- Renderer output for every host expresses the same contract; T5 owns checked-in projection updates.
- Phasewire blocking-finding/remediation invariants remain unchanged.

## Test cases

| # | Scenario | Input or setup | Expected behavior | Notes |
|---|---|---|---|---|
| 1 | Plain review | Ordinary PR review request | Local findings only; no instruction to post | Default safety |
| 2 | Missing target | Posting requested without repository or PR | No write and local fallback | Ambiguous target |
| 3 | Explicit target | Current authorization plus resolved repository and PR | One batched review instruction | Authorized path |
| 4 | Comment spam guard | Inspect rendered policy | No mandatory start/inline/finish comment sequence | Noise and mutation control |
| 5 | Integration | Render every host review adapter in memory | Shared contract present; unconditional write language absent | Cross-host flow |

## Related context

Finding 2; repository product invariant separates derived readiness from external authorization.

## Context

The catalog is the typed source for every host adapter; `AGENTS.md`, the engineering bar, and the review guide currently mirror unconditional GitHub comment instructions. Phasewire review state is durable and local, while GitHub posting is a separate external mutation.

## Gotchas

Review intent is not posting authorization. Authorization without an unambiguous current repository and PR still falls back locally.

## Constraints

Only modify listed files. Keep source doctrine synchronized and leave projection/PR-template work to T5/T10. Do not introduce provider transcript dependence, bypass hooks, or name a tool as repository actor. Return without narrative padding.

## Security constraints

Authorization must be explicit, scoped, current, and target-bound. Never persist tokens, prompts, raw logs, ports, PIDs, or browser state. Do not read `.env*`, certificates, keys, SSH/cloud credentials, or run destructive recursive deletion, `sudo`, `chmod 777`, force-push, or package publication. Report `BLOCKED:` if blocked access is required.

## Output format

Return exactly one: **Completed** with one line per change plus optional future-task notes; `OVERSIZE: <reason>` with a `SUGGESTED-SPLIT:` list; `CONSULT: <peer> — <question>` with at most five context lines; or `BLOCKED: <reason>`.
