# Reuse build artifacts across quality gates

## Task

Consolidate the topological workspace build so static, build, and browser gates reuse prepared artifacts without reducing coverage.

## Why

The current push chain re-enters the same build graph in static checks, workspace build, CI, and Playwright service setup.

## Scope

**IN:** named build/preparation scripts, quality-chain composition, Playwright web-server command, CI reuse, and matching quality-gate documentation.

**OUT:** deleting gates, relying on stale artifacts, introducing remote caching, test assertion changes, or deployment behavior.

## Files in scope

- **Read:** all workspace package scripts and dependency edges — derive the actual topological graph.
- **Modify:** `package.json`, `.github/workflows/ci.yml`, `apps/web/playwright.config.ts`, `docs/quality-gates.md` — reuse the prepared graph and document executable truth.
- **Create:** none.

## Acceptance criteria

- `quality:commit` still enforces structure, lint, typecheck, and unit/integration tests.
- `quality:push` still adds complete workspace build, high-severity audit, and browser acceptance.
- Each required topological build stage runs once per clean quality chain unless an isolated command owns preparation.
- Direct Playwright usage remains deterministic from a clean checkout.
- Documentation describes the resulting executable chain exactly.

## Test cases

| # | Scenario | Input or setup | Expected behavior | Notes |
|---|---|---|---|---|
| 1 | Commit chain | Clean `npm run quality:commit` | Structure, lint, typecheck, and unit/integration tests pass | Hook contract |
| 2 | Push chain | Clean `npm run quality:push` | Build, audit, and browser coverage also pass | Pre-push contract |
| 3 | Build trace | Inspect command trace | Every required topological stage appears once per chain | Performance objective |
| 4 | Direct browser | Clean `npm run test:e2e` | Required preparation occurs and Playwright runs | Local usability |
| 5 | Integration/E2E | Execute cumulative clean push chain | All gates pass with no missing declarations or coverage command | Full story |

## Context

Root scripts compose workspace builds and quality gates, while Playwright's web-server command may prepare server output independently. Reuse must be explicit enough that clean direct commands still own their prerequisites.

## Gotchas

Removing a repeated command is valid only when an earlier command always produces the same required artifacts in clean local and CI entrypoints.

## Constraints

Only modify listed files. Prefer clear named scripts over opaque chains. Do not weaken hooks, alter timeouts, bypass verification, or name a tool as repository actor. Return without narrative padding.

## Security constraints

Retain `npm audit --audit-level=high`, read-only CI permissions, and pinned actions. Add no deployment capability. Do not read `.env*`, certificates, keys, SSH/cloud credentials, or run destructive recursive deletion, `sudo`, `chmod 777`, force-push, or package publication. Report `BLOCKED:` if blocked access is required.

## Output format

Return exactly one: **Completed** with one line per change plus optional future-task notes; `OVERSIZE: <reason>` with a `SUGGESTED-SPLIT:` list; `CONSULT: <peer> — <question>` with at most five context lines; or `BLOCKED: <reason>`.
